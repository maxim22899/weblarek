# Проектная работа "Веб-ларек"

Стек: HTML, SCSS, TS, Vite

Структура проекта:
- src/ — исходные файлы проекта
- src/components/ — папка с JS компонентами

# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

## Данные

Для описания данных в приложении используются следующие интерфейсы:

- `IProduct` - нужен для описания структуры товара.
 Поля: 
 - `id: string` - идентификатор товара.
 - `description: string` - описание товара.
 - `image: string` - ссылка на изображение.
 - `title: string` - название товара.
 - `category: string` - категория.
 - `price: number | null` - цена (может быть `null`, если товар недоступен). 

- `TPayment` - тип, описывающий доступные виды оплаты (например, `'card'` или `'cash'`). 

- `IBuyer` - нужен для описания данных покупателя, которые указываются им при оформлении заказа.
 Поля: 
 - `payment: TPayment` - вид оплаты.
 -  `email: string` - почта.
 -  `phone: string` - телефон.
 -  `address: string` - адрес.

- `TBuyerErrors` - тип, описывающий объект с ошибками валидации данных покупателя (ключи - поля `IBuyer`, значения - текст ошибки).

- `IProductsResponse` - интерфейс ответа сервера при запросе списка товаров.
 Поля:
 - `items: IProduct[]` - массив товаров.
 - `total: number` - oбщее количество.

- `IOrder` - интерфейс заказа, расширяющий `IBuyer`. 
 Поля:
 - `items: string[]` - массив `id` товаров.
 - `total: number` - итоговая сумма.

- `IOrderResult` - интерфейс ответа сервера после оформления заказа. 
 Поля:
 - `id: string` - номер заказа.
 - `total: number` - сумма заказа.

## Модели данных 

Для хранения и управления данными в приложении реализованы три независимых класса (модели данных). Модели отвечают только за хранение данных.

### Класс Каталог (Catalog) 

Назначение: хранит массив всех товаров магазина и товар, выбранный для подробного отображения.

Поля:
-`items: IProduct[]` - массив всех товаров.
-`preview: IProduct | null` - товар, выбранный для подробного отображеня.

Методы:
-`setItems(items: IProduct[]): void` - сохраняет массив товаров, полученный в параметрах.
-`getItems(): IProduct[]` - возвращает массив всех товаров из модели.
-`getItem(id: string): IProduct | undefined` - находит и возвращает один товар по его `id`.
-`setPreview(item: IProduct): void` - сохраняет товар для подробного отображения.
-`getPreview(): IProduct | null` - возвращает товар для подробного отображения.

### Класс Корзина (Basket)

Назначение: хранит массив товаров, выбранных покупателем для покпки.

Поля: 
- `items: IProduct[]` - массив товаров, находящихся в корзине.

Методы: 
- `getItems(): IProduct[]` - возвращает массив товаров в корзине.
- `addItem(item: IProduct): void` - добавляет товар, полученный в параметре, в массив корзины.
- `removeItem(id: string): void` - удаляет товар по его `id` из массива корзины.
- `clear(): void` - очищает корзину.
- `getTotalPrice(): number` - возвращает общую стоимость всех товаров в корзине.
- `getCount(): number` - возвращает количество товаров в корзине.
- `hasItem(id: string): boolean` - проверяет наличие товара в корзине по его `id`.

### Класс Покупатель (Buyer)

Назначение: хранит данные, которые покупатель указывает при оформлении заказа.

Поля:
- `data: IBuyer` - объект, в котором хранятся все данные покупателя (ви оплаты, почта, телефон, адрес).

Методы:
- `setData(data: Partial<IBuyer>: void` - сохраняет данные в модели. Позволяет сохранить не только все поля сразу, но и обновить только одно значение (например, только адрес), не удаляя остальные.
- `getData(): IBuyer` - возвращает все сохраненные данные покупателя.
- `clear(): void` - очищает данные покупателя.
- `validate(): TBuyerErrors` - валидирует данные. Возвращает объект, где ключи - это названия полей, а значения - тексты ошибок. Если поле валидно, его нет в объекте ошибок.

## Слой коммуникации

### Класс LarekApi

Назначение: взаимодействие с сервером для получения товаров и отправки заказов. Использует композицию (внутри себя хранит экземпляр базового класса `Api` из стартового набора).

Поля: 
- `api: IApi` - экземпляр класса для выполнения HTTP-запросов.

Конструктор:
- `constructor(api: IApi)` - принимает объект, соответствующий интерфейсу `IApi`.

Методы:
- `getProducts(): Promise<IProductsResponse>` - делает GET-запрос на эндпоинт `/product/` и возвращает объект с массивом товаров.
- `postOrder(order: IOrder): Promise<IOrderResult>` - делает POST-запрос на эндпоинт `/order/`, передает данные о заказе и возвращает объект с подтверждением покупки (id заказа и итоговая сумма).

## Слой представления (View)

### Класс Header

Назначение: отображает шапку сайта с логотипом, кнопкой корзины и счетчиком.

Данные: `counter: number`.

События: генерирует `basket:open` при клике на кнопку корзины.

### Класс Gallery

Назначение: отображет каталог карточек товаров на главной странице.

Данные: `catalog: HTMLElement[]`.

### Класс Modal

Назначение: управляет показом и скрытием модальног оокна.

Методы: `open(content: HTMLElement)`, `close()`.

События: генерирует `modal:close`.

### Базовый класс Card

Назначение: общий предок для всех карточек товара.

### Класс CardCatalog (наследуется от Card)

Назначение: карточка товара в каталоге

События: генерирует `card:select` при клике на карточку.

### Класс CardPreview (наследуется от Card)

Назаначение: Подробная карточка товара в модальном окне.

События: генерирует `card:buy` или `card:remove` при клике на кнопку. 

### Класс CardBasket (насдедуется от Card) 

Назначение: карточка товара в корзине.

События: генерирует `basket:remove` при клике на кнопку удаления.

### Класс Basket 

Назначеине: отображение списка товаров в корзине и общей суммы.

Данные: `items: HTMLElement[]`, `total: number`.

События: генерирует `basket:order`.

### Базовый класс Form<T>

Назначение: общий порядок для форм. Отвечает за валидацию, ввод данных и блокировку кнопок.

События: генерирует `form:change` при вводе.

### Класс OrderForm (наследуется от Form) 

Назначение: Первая форма оформления (оплата и адрес).

События: генерирует `order:submit`.

### Класс ContactsForm (наследуется от Form)

Назначение: вторая форма оформления (почта и телефоон).

События: генерирует `contacts:submit`.

### Класс Success

Назначение: окно с сообщением об успешной оплате.

События: генерирует `success:close`.
